# 00.02 — Computer Fundamentals

## Learning Objective

By the end of this lesson, you should be able to:

* Explain the roles of the CPU, RAM, storage, and input/output devices.
* Understand how a program gets loaded and executed.
* Distinguish between a program, a process, and a thread.
* Explain how files and data are stored and accessed.
* Understand why computing resources affect an application's speed, capacity, and reliability.

> The goal is to understand what happens inside a computer when your application runs — without needing to become a hardware engineer.

---

## 1. What Is a Computer?

A computer is an electronic system that accepts data, processes it, stores information, and produces results.

At a simplified level:

```text
Input → Processing → Output
             ↕
           Storage
```

For example, when you open a web application on your computer:

1. You provide input through the keyboard or mouse.
2. The CPU executes instructions belonging to the application.
3. RAM holds the data and instructions currently being used.
4. Storage keeps application files and saved data.
5. The display shows the result.

These components work together. None of them, by itself, represents the entire computer system.

A computer's major components have different responsibilities.

| Component          | Main responsibility                                       |
| ------------------ | --------------------------------------------------------- |
| CPU                | Executes instructions and performs calculations.          |

## 3. CPU — The Processor

**CPU stands for Central Processing Unit.**

The CPU executes instructions. These instructions tell the computer to perform operations such as calculations, comparisons, and moving data.

For example, consider this JavaScript:

```javascript
const price = 500;
const quantity = 3;

const total = price * quantity;
```

The CPU executes the machine instructions generated from the program to perform the calculation.

The CPU does not directly understand JavaScript. A JavaScript engine and other software components translate and execute the program using instructions the processor can execute.

### What affects CPU performance?

Two important concepts are:

**Clock speed:** How frequently the processor's clock cycles occur. It is commonly measured in GHz.

**CPU cores:** Individual processing units within a CPU that can execute instruction streams independently.

A multicore CPU can execute work on multiple cores at the same time, subject to the operating system, available resources, and the nature of the workload.

```text
              CPU
      ┌────────┼────────┐
      ▼        ▼        ▼
    Core 1   Core 2   Core 3
      │        │        │
      ▼        ▼        ▼
    Task A   Task B   Task C
```

This does not mean every application automatically becomes three times faster with three cores. Some work must happen sequentially, and tasks can compete for shared resources.

### Why CPU matters in system design

Suppose your application performs heavy image processing or complex calculations.

As the number of requests increases, CPU usage may rise.

If the CPU becomes saturated, requests may wait longer before being processed.

This is a potential CPU bottleneck.

**Remember:** Adding more application servers may increase total processing capacity, but only if the workload can be distributed and another resource does not become the limiting factor.

## 4. RAM — Working Memory

**RAM stands for Random Access Memory.**

RAM temporarily holds the data and instructions that the computer is actively using.

Think of RAM as a working desk.

Storage is the cupboard where you keep your files. RAM is the desk where you place the files you are currently working on.

```text
Storage                       RAM
┌───────────────┐             ┌───────────────┐
│ Application   │ ── Load ──► │ Active data   │
│ files         │             │ and code      │
│               │             │               │
│ Saved data    │             │ Running       │
│               │             │ application   │
└───────────────┘             └───────────────┘
```

RAM is volatile memory. Its contents are normally lost when power is removed.

### Example: A web server

Imagine an application server with 4 GB of RAM.

Its memory is used by:

* The operating system.
* The application runtime.
* The application itself.
* Active requests and their data.
* Other running services.

The application cannot safely assume that all 4 GB is available for its own use.

As more requests are processed concurrently, memory consumption may increase.

If memory pressure becomes too high, the operating system may reclaim memory, use swap space, or terminate processes.

### Why RAM matters in system design

Consider a server handling hundreds of concurrent requests.

Each request requires memory for its processing.

If each active request consumes additional memory, increasing concurrency can increase total memory usage.

A simplified model:

$$
\text{Memory Usage} \approx
\text{Base Memory} +
(\text{Active Requests} \times \text{Memory per Request})
$$

This is an approximation, not a universal formula. Real applications share memory, allocate memory dynamically, and release it at different times.

**System-design lesson:** More concurrent users can require more memory, even when CPU usage is not especially high.

## 5. Storage — Persistent Data

Storage keeps data even after the computer is switched off.

Common examples include:

* HDD (Hard Disk Drive)
* SSD (Solid State Drive)
* NVMe SSD

<AsyncImageGroup query={["hard disk drive HDD opened platter","NVMe M.2 solid state drive","SATA SSD storage drive"]} aspectRatio="5:4" layout="carousel"/>

Applications use storage for:

* Program files.
* Uploaded images and documents.
* Database files.
* Logs.
* Configuration files.
* Backups.

### RAM vs Storage

| RAM                                          | Storage                                        |
| -------------------------------------------- | ---------------------------------------------- |
| Temporary working memory                     | Persistent data storage                        |
| Volatile                                     | Non-volatile                                   |
| Usually much faster for active memory access | Generally slower than RAM                      |
| Limited capacity                             | Typically larger capacity at lower cost per GB |

For example, a database may store its data on an SSD. When a query runs, the database can load relevant data into memory and use caches to reduce repeated storage access.

However, databases also use specialized techniques to manage memory, durability, and disk I/O.

### Why storage matters in system design

Imagine an application that stores millions of customer records.

Storage capacity determines how much data can be retained.

Storage performance affects how quickly data can be read or written, although database indexes, caching, query design, and other factors also matter.

**Important distinction:** Having enough storage capacity does not guarantee fast database queries.

## 6. Input and Output (I/O)

I/O means Input/Output.

It describes the movement of data into or out of a computer or a component.

Examples:

| Operation                            | Type   |
| ------------------------------------ | ------ |
| Reading a file from an SSD           | Input  |
| Writing a database record to storage | Output |
| Receiving an HTTP request            | Input  |
| Sending an HTTP response             | Output |
| Receiving data from a network        | Input  |
| Sending data over a network          | Output |

I/O is not limited to keyboard, mouse, or monitor operations.

For servers, network and storage I/O are particularly important.

### A simple example

Suppose a web application receives a request to display a customer's order history.

```text
Browser
   │
   │ HTTP Request
   ▼
Application Server
   │
   │ Database Query
   ▼
Database
   │
   │ Query Results
   ▼
Application Server
   │
   │ HTTP Response
   ▼
Browser
```

The application performs CPU work, but it also waits for network communication and database access.

A request that spends most of its time waiting for I/O may not need a faster CPU. It may need better query performance, reduced network latency, or more efficient I/O.

This brings us to a crucial distinction:

**CPU-bound vs I/O-bound work**

| CPU-bound                                             | I/O-bound                                                            |
| ----------------------------------------------------- | -------------------------------------------------------------------- |
| Performance is mainly limited by processing capacity. | Performance is mainly limited by waiting for data or I/O operations. |
| Example: video encoding or heavy calculations.        | Example: waiting for a database response or remote API.              |
| More CPU capacity may help.                           | Better I/O efficiency, concurrency, or reduced waiting may help.     |

Real applications can be limited by different resources at different times.

## 7. What Happens When a Program Runs?

A program is a set of instructions stored as code or executable files.

A program sitting on storage is not necessarily executing.

To run a program, the operating system and its supporting components arrange for the program to be loaded and executed.

A simplified lifecycle:

```text
      Program on Storage
              │
              ▼
     Operating System
              │
              ▼
       Process Created
              │
              ▼
    Memory and Resources
              │
              ▼
       CPU Executes
        Instructions
              │
              ▼
         Program Runs
```

Let's use a familiar example.

You open a browser on your computer.

1. The browser's executable files and required data are accessed from storage.
2. The operating system creates and manages the browser's process or processes.
3. Memory is allocated for the running program.
4. The CPU executes instructions.
5. The browser performs I/O, renders pages, and responds to user actions.

This is a simplified model. Modern operating systems and application runtimes perform many additional operations, including dynamic loading, memory mapping, security checks, and process initialization.

### Program vs Process

These two terms are not interchangeable.

**Program:** The instructions and related files that describe what a computer should do.

**Process:** A running instance of a program, managed by the operating system.

For example:

```text
Browser Program
      │
      ├────► Browser Process A
      │
      └────► Browser Process B
```

The same program can have multiple running instances or processes.

A process has resources and execution context managed by the operating system, including a virtual address space and operating-system-managed resources.

## 8. Process and Thread

A process is a running program. A thread is an execution path within a process.

A process can have one or more threads.

```text
              Process
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
     Thread 1 Thread 2 Thread 3
```

Threads within the same process typically share the process's memory and resources, while each thread has its own execution state and stack.

### A practical example

Imagine a desktop application that:

* Downloads a file.
* Updates the user interface.
* Processes some data.

If all work happens sequentially on one execution thread, a slow download or long calculation can make the interface unresponsive.

A multithreaded design can allow some work to happen concurrently.

```text
Application Process
        │
        ├── UI Thread
        │     └── Updates interface
        │
        ├── Worker Thread
        │     └── Processes data
        │
        └── Worker Thread
              └── Handles background work
```

This diagram illustrates a possible design, not a requirement that every application must use multiple threads.

### Process vs Thread: Quick Comparison

| Process                                          | Thread                                                   |
| ------------------------------------------------ | -------------------------------------------------------- |
| A running program instance                       | An execution path within a process                       |
| Has its own virtual address space                | Shares process memory with other threads                 |
| Provides stronger isolation from other processes | Usually requires coordination when accessing shared data |
| Process communication can require IPC mechanisms | Threads can communicate through shared memory            |

**Important:** Threads are not automatically faster. Coordination, shared-resource contention, and synchronization can introduce overhead and bugs.

We will explore processes, threads, scheduling, and memory management in detail in the Operating Systems chapter.

## 9. Files and File Systems

A file is a named collection of data.

Examples:

```text
index.php
style.css
logo.png
users.csv
database.sqlite
```

A file system is the mechanism the operating system uses to organize and manage files on storage devices.

It typically manages:

* File names and directories.
* File metadata.
* File locations and storage allocation.
* Access permissions.
* Reading and writing file contents.

A simplified structure:

```text
Storage Device
      │
      ▼
  File System
      │
      ├── /app
      │     ├── index.php
      │     └── style.css
      │
      ├── /uploads
      │     └── image.png
      │
      └── /logs
            └── application.log
```

The application usually asks the operating system to access files rather than directly controlling the physical storage device.

### Why this matters

Consider a web application that accepts customer uploads.

Questions a system designer should ask:

* Where are uploaded files stored?
* What happens when storage becomes full?
* Can multiple application servers access the same files?
* Are files backed up?
* What happens if the storage device fails?

These questions become especially important when moving from one server to multiple servers or to cloud infrastructure.

## 10. Putting It All Together

Let's follow a request through a simplified web server.

A customer opens a page showing product information.

```text
                  USER
                    │
                    ▼
                Browser
                    │
                    │ HTTP Request
                    ▼
              Network I/O
                    │
                    ▼
             Application Server
                    │
             ┌──────┴──────┐
             ▼             ▼
            CPU           RAM
        Executes       Holds active
        instructions   data and code
             │             │
             └──────┬──────┘
                    │
                    ▼
                Database
                    │
                    ▼
               Storage I/O
                    │
                    ▼
             Database Results
                    │
                    ▼
              Application
                    │
                    ▼
              HTTP Response
                    │
                    ▼
                 Browser
```

This is a conceptual diagram. Actual systems may include database caches, connection pools, reverse proxies, multiple network hops, and other components.

Notice that the request depends on several resources:

| Resource         | Role in the request                                      |
| ---------------- | -------------------------------------------------------- |
| CPU              | Executes application and database instructions.          |
| RAM              | Holds active application data and database caches.       |
| Storage          | Persists database records and files.                     |
| Network I/O      | Carries requests, responses, and database communication. |
| Operating system | Manages processes, memory, files, and hardware access.   |

A slow request may result from any of these resources or from the way the application uses them.

**System-design principle: Identify the constrained resource before choosing a solution.**

## 11. Common Beginner Mistakes

| Mistake                                           | Correct understanding                                                           |
| ------------------------------------------------- | ------------------------------------------------------------------------------- |
| CPU and RAM are the same thing.                   | CPU executes instructions; RAM holds active data and instructions.              |
| Storage and RAM are interchangeable.              | Storage is persistent; RAM is working memory.                                   |
| A program and a process are the same.             | A program contains instructions; a process is a running instance.               |
| Every process has only one thread.                | A process can contain multiple threads.                                         |
| More CPU cores always make an application faster. | The workload must be able to use the additional processing capacity.            |
| Every slow application needs a faster server.     | The bottleneck could be CPU, memory, storage, network, or inefficient software. |
| I/O means only keyboard and mouse.                | I/O includes file, storage, network, and other data transfers.                  |

## Architecture Insight

A web application does not run in isolation. It relies on the operating system, processor, memory, storage, and network.

When the number of users increases, resource consumption may increase as well.

Understanding these resources helps explain why systems need capacity planning, performance measurement, and eventually scaling.

> **A system can only perform as well as its available resources and the way it uses them.**
